Root cause: the issue-fix adapter is passing `type: "adaptive"` in the thinking block, but the API endpoint only accepts `"disabled"` or `"enabled"`. This indicates either:
- The adapter was recently updated to use an adaptive thinking flag that has not yet been deployed to the API, or
- A version mismatch between the adapter config and the API contract.

Action required: locate the thinking block configuration in the issue-fix adapter and change `type: "adaptive"` to `type: "enabled"` (or consult the API changelog for the correct parameter). All 11 failed repos can be retried once this is corrected — none failed due to repo-specific incompatibility.
