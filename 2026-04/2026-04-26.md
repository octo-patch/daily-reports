### 3. Issues & Failure Analysis

- **All 6 failures share the same root cause**: The worker passed `type: 'adaptive'` to the Claude API's thinking parameter, but the API only accepts `'disabled'` or `'enabled'`. Error message: `thinking: Input tag 'adaptive' found using 'type' does not match any of the expected tags: 'disabled', 'enabled'`. This is a **bot-side configuration bug**, not a repo incompatibility. It appears to be a regression — likely introduced when an API version change tightened validation on the `thinking` field. Fix: update the worker's API call to use a valid thinking mode value.
- **This issue is systematic and repeatable**: 6 out of 6 failures are identical, all occurring at API call time before any repo processing. The affected repos were not structurally different from successful ones.
- **Skipped pattern — inactive repos**: 3 repos exceeded the 12-month inactivity threshold. The queue still contains these repos; the upstream task selection should filter by `pushed_at` before enqueuing to avoid wasted evaluation cycles.
- **Skipped pattern — competing PRs**: Several repos (HKUDS/ClawWork, rig, enterprise multi-agent) had all bug issues covered by existing open PRs. This is upstream task selection noise — consider checking open PR count per issue before assigning.
- **No timeout failures today**, which suggests network and execution environments were stable.
