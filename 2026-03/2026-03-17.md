### 3. Issues & Failure Analysis

**OOM failures (5 workers, exit=134):**

All five are JavaScript heap out-of-memory crashes in the Claude process itself, not in the target repo's toolchain. Stack traces show failures in V8's young-generation allocation (`NewSpace::EnsureCurrentCapacity`, `AllocateInYoungGeneration`). Heap size at crash was consistently in the 77–99 MB range. This is a bot infrastructure issue, not a target repo issue. Possible causes:

- Repos with very large codebases loaded into context simultaneously with test output
- Accumulation of background task output before GC can run

Recommended action: Investigate whether any of the 5 failed sessions were retried; if not, re-queue those repos. Consider adding a `--max-old-space-size` flag to the Claude process if configurable, or reducing parallel context loaded per session.

**Timeout failures (6 workers):**

- cc2bb743 (TabbyML/tabby): 5400s timeout. This repo is likely large and complex. The session held a "处理中" lock all day, blocking other workers from picking it up. The lock should be released and the task re-queued with a more targeted analysis scope.
- f3b1a98b: 5400s timeout. No repo context in logs; insufficient data to determine root cause.
- 4 additional timeout-attributed workers: Based on worker health stats (6 Timeout/Error), the remaining 4 likely hit network issues (git fetch/clone timeouts). The harbor session (bb6a59cc) documents a successful workaround using gh-proxy.com, suggesting GFW-related network instability affected multiple workers.

**No Task sessions (21):**

These are not failures. The task queue was fully depleted by mid-afternoon. The 21 no-task sessions represent normal queue drain behavior — workers launched after queue exhaustion found nothing to process. This volume of idle workers suggests the launch schedule should be throttled once the queue approaches empty.

**Patterns in skipped repos:**

The dominant rejection reason is "no external LLM API." The upstream task selection pipeline is pulling in a significant proportion of repos that are frontend plugins, local model runners, or hardware tools. Filtering candidates by presence of HTTP API call patterns (e.g., `requests.post`, `fetch`, `axios`, `openai.chat.completions`) before queuing would reduce wasted worker time.
