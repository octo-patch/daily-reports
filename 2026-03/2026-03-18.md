### 3. Issues & Failure Analysis

**Timeouts (16 in Update Tasks)**

- Root cause: network-level failures when attempting direct `git fetch` or `git push` to `github.com` from the worker environment
- Mitigation applied during the session: workers switched to `gh-proxy.com` as a proxy and completed successfully in most cases
- Two workers (`81bc048f`, `c349e162`) hit the hard 3600s timeout ceiling and did not recover — repos assigned to these sessions have no confirmed outcome and should be requeued
- This is a recurring infrastructure pattern: direct GitHub connectivity is unreliable; proxy fallback should be the default rather than a manual workaround

**Rejected repos (upstream task selection)**

All 3 rejections are upstream selection issues — these repos were queued as LLM-compatible but do not make external API calls. Filtering criteria for the task queue should be reviewed to exclude:
- Video generation pipelines without API backends
- ComfyUI custom nodes that implement sampling algorithms rather than model routing
